# Migration to Workflow v3

Date: 2026-10-31
Status: implemented
Scope: control-plane development jobs, guard timeout, OpenCode profiles.

## Summary

Workflow v3 adds a durable development-job CLI around the existing execution
guard and OpenCode. It does not change platform source, the Qortium node, system
services, the interactive OpenCode `build` agent or the existing restricted
unattended profile.

The execution guard's hard maximum is now **8 hours** (previously 4 hours), and
the default for both the guard and `dev start` is 8 hours. Values above 8 hours
are rejected.

## What changed

| Area | Before | After |
| --- | --- | --- |
| Guard maximum | 4h / 14400s | 8h / 28800s |
| Guard default | 4h | 8h |
| Background execution | tmux or direct terminal | detached job session (no tmux required) |
| Job records | optional `STATUS.json` per task | durable JSON state + events + logs + report |
| Success rule | human review of exit code/evidence | verified acceptance criteria + no detectors |
| Resume | start a new guarded command manually | `dev resume` reuses the job/session/worktree |
| Notifications | none | optional Telegram final-state notifications outside Git |
| Development profile | restricted only | new `opencode-development` profile with hard boundaries |
| Qortium safety | guard read-only + profile denials | preserved and extended in the new profile |

## Compatibility

- Existing task artifacts under `tasks/` are unchanged and remain valid.
- `templates/STATUS.json` schema version 2 is unchanged; Workflow v3 state lives
  in the external job store, not in task STATUS.
- The existing `opencode-unattended` profile remains for restricted work.
- The guard's `check`/`run` command line stays compatible. `--pid-file` is a
  new optional argument.
- No existing job is automatically adopted. Start a new `dev start` job or keep
  using the manual guard workflow.

## Upgrade steps

1. Pull the Workflow v3 branch and run the validation suite:

   ```bash
   python3 tools/test_opencode_guard.py
   python3 tools/test_dev_cli.py
   python3 tools/validate_control_plane.py
   python3 tools/validate_skills.py
   python3 tools/validate_security.py .
   ```

2. Install the agent profiles if they are not already present:

   ```bash
   tools/install_opencode_profiles.sh
   ```

   Restart OpenCode afterwards because agent profiles load at startup.

3. Optionally link the CLI into a user-local bin directory:

   ```bash
   mkdir -p ~/.local/bin
   ln -sf "$PWD/tools/dev.py" ~/.local/bin/dev
   ```

4. Optionally create `~/.config/dev-control-plane/telegram.json` with mode
   `0600`. Keep the token and chat ID outside Git. Leave it absent to disable
   notifications.

5. Start an authorized job with explicit acceptance criteria and verify the
   eight-hour default:

   ```bash
   dev start --title "migration smoke" --repo . --prompt "..." \
     --criterion "tests::python3 -m pytest -q" --dry-run
   ```

## Rollback

The change is additive except for the guard maximum. To roll back:

1. restore `MAX_TIMEOUT_SECONDS = 4 * 60 * 60` (and the help text/tests);
2. stop using the `dev` CLI; existing job directories are inert files under
   `~/.local/state/dev-control-plane`;
3. leave the installed development profile in place or remove only the
   `opencode-development.md` file;
4. keep any Telegram config outside Git or delete it.

Do not roll back by stopping or reconfiguring Qortium, and do not run
`git clean`, `git reset --hard`, `pkill` or `systemctl` on the live host.

## Evidence

Implementation evidence is recorded in the task branch and the final report.
The guard tests assert the 8-hour default, the 8-hour maximum and rejection of
9h. The CLI tests assert that exit code `0` with a failing acceptance command is
`FAILED`, that permission/missing-dependency signals become `BLOCKED`, and that
step exhaustion/incomplete implementation become `FAILED`.
